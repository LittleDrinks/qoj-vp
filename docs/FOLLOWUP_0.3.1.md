## L 重复记录的原因和修复

真实浏览器安全诊断确认：`4569 / L / 23137` 的一次 POST 返回 HTTP 302，Location 为 `/contest/4569/submissions`。浏览器正确捕获了回执，但地址没有提交 ID，因此 CLI 报 UnknownSubmission；历史随后导入 `3338719`，未与本地操作关联。

现在通过只读历史与提交详情恢复关联：账号、比赛、题目、语言、绝对提交时间和完整源码 SHA-256 必须匹配，候选和操作必须唯一。对 HTML 换行归一仅比较完整 LF / CRLF 两种字节形式，不裁剪空白。源码不写入账本或诊断。已有未知记录也会在正常刷新时核对；核验失败保留未确认状态，绝不自动重发源码。

这次真实 L 的浏览器源码展示是 LF，本地原文件是 CRLF；恢复 CRLF 后 SHA 与本地操作完全相同。`3338715` 为已有 M 提交，验证不通过重新提交来构造。
